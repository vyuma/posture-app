# キャラクター選択画面のセリフとモーション

2026-10-29。Web PiiiN / macOS posture-app に反映。

## 実装

- カード描画が参照する `src/features/work/characterPresentation.json` に `pickerSpeech` を追加。17種すべてに性格タグと説明に合わせたセリフを用意し、シマアナゴは指定どおり `頑張ろう！`。
- `\n` は推奨改行。例: ヨゾラナゴは `静かに、\nそばにいるよ。`。オトアナゴはユーザーの指定を受け `眠い・・・` に修正。欠損時はシマアナゴのセリフへフォールバックする。
- 選択したIDをキーに、既存の白い吹き出しが尾の付近を中心に1px程度・1%程度だけ動く。文字は38ms間隔、句読点には100msの間を設け、140msで表示。発話の終了後は元の8度の角度で静止する。無限ループ・タイマー・新しい依存パッケージはない。
- `prefers-reduced-motion: reduce` では吹き出しと全文を直ちに静止表示。読み上げ用の領域は安定して保持し、キャラクター名と全文を一度に伝える。アニメーション用の各文字は読み上げ対象外。
- ホームの呼吸、カードのホバー、ストーリー等の既存アニメーションには変更なし。選択・決定・キャンセルの保存動作も変更なし。

## 影響範囲

変更ファイルは `Home.tsx`、`CharacterCard.tsx`、`characterPresentation.json`、新規 `CharacterSpeech.tsx` と `character-speech.css`。WebとDesktopで同一。

共有カタログのID・名前・性格・希少度・画像・イベント/APIには変更なし。モバイルのカタログも比較し、今回はWeb/Desktop選択画面専用の表示設定なので、当該画面もJSONもないvibe-appへ未使用フィールドを追加していない。

作業時のリモートmain: PiiiN `d3c75b7e` / posture-app `7c0f7f86` / vibe-app `053104b4`。作業中の既存変更を維持し、コミット・pushはしていない。

## 実行した検証

- ブラウザで17種すべてを選択し、画像・読み上げ用全文・表示するセリフが一致することを確認。短い間隔での連続選択でも最後に選んだキャラクターのセリフへ切り替わる。
- 発話途中に文字のopacityが `1 → 0.91 → 0.66 → 0.32 → 0` と段階的に表示され、終了後には全て1になることを実測。吹き出しも終端のrotate(8deg)へ戻る。
- Web 1512×982 / 720×512 / 390×844で実表示。長めのコイアナゴの2行も吹き出し内に収まり、ページの横オーバーフローなし。元の吹き出しの位置・尾・白色・角度は維持。
- キーボードEnterでキャラクターを選択でき、フォーカス/選択枠を確認。0枚の初期状態では吹き出しなし、決定は無効。
- macOSの開発アプリで実際に選択画面を開き、シマアナゴ→オトアナゴの切り替え、文字が現れる途中と終了状態を確認。1200×752 / 720×512の両方で表示を確認。
- JSONの17種の網羅・空文なし・異なるセリフ・シマアナゴの固定文言を検証。
- 両リポジトリの `bun run build`、Desktopの `cargo check --manifest-path src-tauri/Cargo.toml`、`git diff --check` 成功。既存のlottie eval、chunkサイズ、未使用ペアリングコード等の警告は残る。
- Reactレビュー: 状態やeffectを増やさず、描画時にデータを導出。選択中に不要な再生が起きないキー、タイマーのない終了処理、読み上げの分離を確認。
