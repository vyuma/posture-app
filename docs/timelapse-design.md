# タイムラプスとコレクション詳細カード — 設計対話

状態: 2026-10-28に利用者が計画を承認し、Web / Desktopへ実装。以下の推奨既定動作も承認済み。実行検証の結果は docs/timelapse-verification.md に記録する。

## 確定した希望

- 対象は既存の Web / Desktop。測定中の実際のカメラ映像を振り返る機能で、スコアやキャラクターだけの再生ではない。
- 取得・未取得の結果画面から「タイムラプスを見る」で再生画面に進む。
- 結果画面を閉じた後の再閲覧は、コレクションカードから取得済みの動画を開く方式とする。独立した動画一覧は追加しない。未取得動画は結果画面から再生・保存・共有できるが、閉じた後の再閲覧入口は設けない。この動線の決定だけを理由に原本を自動削除せず、合意済みの保持方針を維持する。
- 再生開始時は1倍速にしたい。ボタンを押すと倍率の数値が切り替わる。倍率は1→2→4→6→8→16→1。
- 独立した常設の再生・一時停止ボタンは設けない。動画そのもののクリック／タップで再生・一時停止を切り替え、切り替わった操作を示すアイコンを動画中央へ一時的に重ねて消す。YouTubeの操作フィードバックに近い意図で、再生したときは再生アイコン、一時停止したときは一時停止アイコンを表示する。
- 任意の再生位置へ移動できるシークバーと、Figmaの動画枠外にある倍率ボタンは維持する。バーをクリック／ドラッグしても再生切り替えを誤発火させない。シーク後も、映像内の測定ペット・残り時間・サイクルを同じ位置へ同期する。
- 録画対象は集中時間だけ。休憩・一時停止・基準再登録を除外し、集中を再開した区間を順につなぐ。集中25分＋休憩5分＋集中25分なら、全区間を記録できた場合の1倍速映像は50分。
- タイマー設定にタイムラプス記録の選択肢を設ける。初回はオフで、利用者が変更した選択を次回以降も記憶する。
- 録画品質は720pを既定とし、設定から1080pも選択できるようにする。1080pは任意の選択肢であり、全利用者へ強制しない。希望品質をカメラが満たせない場合の扱いは実際の取得解像度を確認して具体化する。
- タイムラプスの保存・共有を提供する。現在の大会・準備用途では、アプリ内映像を利用者がデータ削除するまで保持し、経過日数による自動削除は行わない。7日保管は正式リリース時の検討事項で、現時点では適用しない。対応を検出してMP4/H.264を優先し、非対応環境ではWebMを使用する。
- コレクション初期化では、カードと併せてアプリ内のタイムラプス映像も削除する。初期化確認文にも映像の削除を明記する。測定スコアの記録と、アプリ外に書き出したファイルは残す。
- 保存・共有の既定はカメラ映像のみ。映像内の測定ペットを含めるかは利用者が選ぶ。外側の背景・左右の装飾アナゴを含める設定は、測定ペットの設定とは別の選択肢として、ホームのプロフィール →「設定」に用意する。
- 測定ペットを含める場合は、アナゴ本体に加えて当時の残り時間・サイクル表示も含める。表情・ポーズ・動きと各表示値を同じ録画の再生位置に同期させる。休憩等を除いて集中区間をつなぐ際も、残り時間・サイクルを動画の総尺から推定せず、該当する集中区間の記録を使う。
- 保存・共有する動画は、プレイヤーで選択した倍率にかかわらず常に1倍速とする。カメラのみ・背景とアナゴを含める構成のどちらでも、記録した集中区間の実時間を維持する。
- 録画・再生・保存・共有はすべて無音。マイク音声は取得しない。
- 構成編集はアプリ内の映像構成を対象とし、PC画面・他のウィンドウの録画は含めない。プリセット選択に限定せず、利用者が直接ドラッグとサイズ変更で自由に配置する希望は維持するが、左右の装飾アナゴを自由配置の対象に含めた以前の解釈は撤回する。映像内のカメラ・測定ペットを編集対象にする。
- 構成の保存方法は「保存しやすく、アプリが重くならない方」を優先するよう利用者から委任されたため、全動画共通の現在の配置設定を1つ保存する方式を採用する。過去の録画にも現在の設定を適用し、すでに外部へ書き出したファイルは変更しない。
- カメラ原本を保持し、配置変更のたびに動画を複製しない。背景・アナゴを含む動画は保存・共有を実行するときに合成する。カメラのみの出力は可能な限り再エンコードを避ける。短時間の書き出しは検証済み。長時間の速度・メモリ負荷は検証記録の制限事項を参照。
- 映像の外側にいる左の装飾アナゴはシマアナゴ、右は取得したキャラクターで、未取得時は現在の未取得カードに使う灰色のアナゴ。両側ともデザイン上の位置に固定し、測定時の姿勢反応を担当させない。外側の背景とアナゴを含む書き出しでも同じ組み合わせを使う。
- 測定当時の状態・アニメーション変化を振り返る対象は、映像の中に表示する測定ウィジェット／デスクトップペット。外側の左右の装飾アナゴとは別物である。左右のどちらに姿勢反応を持たせるかという前の質問は誤解に基づくため撤回する。
- 新画面へ入る際に左右2体が下から現れる演出は以前の希望として残すが、到着位置は固定する。位置固定を新たな常時移動や揺れの許可とは解釈せず、既存アニメーションも変更しない。
- コレクション詳細カードは添付「クリック時」CSSに合わせて日時の位置だけ変更。他の見た目は現行を保つ。
- コレクション詳細から保存する画像は取得時の結果カードのデザインを使う。

## 実装前に確認した状況

- 両リポジトリの対象コードにタイムラプス、MediaRecorder、captureStream の実装はない。
- 測定セッションは時刻・集中時間・姿勢スコア・イベントを持つが、カメラ映像は保存しない。過去の測定データから実写映像は復元できない。
- 現在のカメラ要求は前面カメラ、希望1280×720、音声なし。タイムラプスの720p既定はこの取得要求と整合するが、実際に取得できる解像度は端末で確認する必要がある。
- Web は IndexedDB、Desktop は SQLite に測定記録を保存する。動画の保存方式はまだ決めていない。
- 添付タイムラプスの基準画面は1512×982、白パネル936×729、動画枠768×451。動画枠はプレースホルダーで、録画内容・切り抜き方を規定しない。
- 添付「クリック時」の日時は911.39×517カード内の left:410 / top:27。ユーザー指定は位置だけなので、添付に残る旧グラフ色などは適用しない。
- 現在のホームのプロフィールメニューは「サウンド設定」「ストーリーを見る」「コレクションを初期化」。総合的な「設定」への入口はまだない。
- Web / Desktop の `PetRig.tsx` はシマアナゴ専用の Lottie で good / bad / paused 間を遷移する。`Widget.tsx` は悪い姿勢が続く間の拡大と、CSSによる揺れも加える。既存のスコアサンプルだけでは、画面に表示した各状態変化の時刻やアニメーションの途中位置まで保証できない。
- 測定ウィジェットはカメラ映像とは別に描画されるUIで、カメラの映像トラックだけを録画しても映り込まない。映像内に表示・書き出しするには、別途ペットを合成する必要がある。

## 承認された既定動作

以下を含む計画全体について、2026-10-28に利用者が「この計画で確定し実装開始」を選択した。

- 倍率は 1→2→4→6→8→16→1 と巡回する。動画を開いたら1倍速で再生開始し、自動再生できない場合は動画のクリック／タップで再生できることを案内する。最後まで再生したら停止し、動画をクリック／タップすると先頭から見直せるようにする。常設の再生ボタンは追加しない。
- 右上の閉じる操作は元の結果画面またはコレクション詳細カードへ戻る。既存の「ホームに戻る」はホームへ移動する。設定・保存画面へ移っただけで測定記録や原本を失わない。
- 1080pを取得できない機器では取得可能な品質へ下げ、実際の画質を表示する。設定変更は次の録画から反映し、過去の720p原本を1080pとして水増ししない。
- 容量不足や録画障害時は既存動画を自動削除せず、録画の停止を知らせる。姿勢測定・スコア・カード取得は続行し、安全に確定できた映像は部分記録として残す。未録画、保存中、部分記録、利用不可を区別し、映像がない過去のカードには再生できるように見せない。
- 自由配置は動画内のカメラと測定ペットを対象にする。ペットの本体と情報欄は一組で移動・拡大縮小し、見切れを防ぐ。動画外の左右のアナゴは編集対象にしない。共通設定とプレビューを使い、保存・共有の見た目を確認できるようにする。
- 動画の共有はファイル共有として扱う。画像のクリップボード処理をそのまま転用せず、環境がファイル共有に対応しない場合は保存して添付できる導線を出す。自動で外部サービスへアップロードしない。

## 承認済み実装計画

### 1. 対象と境界

WebのPiiiNとTauriのposture-appを変更する。キャラクターID、カタログ、LAN通信契約、モバイルアプリには変更を加えない。2026-10-28に3リポジトリの遠隔HEADを再確認した: Web `d3c75b7e8b357e12ded0627b7a128a8a86e400cd`、Desktop `7c0f7f865f45abdacdf039c3c3ce1d7279742bef`、Mobile `053104b4c8348ed0f6cec5406cf87e066001f628`。既存の未コミット変更を保持し、製品コードへ着手する直前にも差分を確認する。

### 2. 最初に検証する録画・出力経路

既存カメラの映像トラックを共有して録画し、マイクや画面共有の権限は追加しない。MediaRecorderを第一候補として、利用可能な形式・実際の解像度・pause/resume・最終チャンク保存・再生とシークをWebと実際のTauri WebViewで確認する。MP4/H.264を優先候補とするが、一律に利用できるとは決めつけず、対応するWebM等も能力検出に基づいて扱う。

カメラだけの保存では、可能な限り再エンコードせず原本を出力する。ペット／外側の装飾を含む出力は同じ再生時刻を使って合成し、常に1倍速の時間軸で書き出す。WebCodecsとコンテナ処理用ライブラリを必要時だけ読み込む案を比較し、大きな変換エンジンを常時読み込む構成は避ける。Mediabunny 1.62.1を必要時だけ読み込む。互換性・処理時間は検証記録を参照。合成非対応ならカメラのみへ無言で切り替えず、理由と利用できる保存方法を表示する。

### 3. 記録と同期

`WorkApp.tsx`の測定進行、休憩、一時停止、基準再登録、終了処理に録画制御を接続する。状態更新の順序を一箇所で管理し、集中区間だけを録画へ反映する。終了時はカメラを解放する前に録画停止とデータ確定を開始し、タイムラプス側が保存中でもカード結果を表示できるようにする。

セッションIDに紐づくタイムラプスメタデータを追加する。内容はスキーマ版、録画状態、実際の形式・解像度・尺・バイト数、保存単位、集中区間との対応、コレクション世代、測定ペットの状態変化記録とアニメーション資産の版。既存セッションは映像なしとして読み込めるようにし、既存のスコア計算とカード取得規則は変えない。

測定ペットには実際に表示へ渡した姿勢・遷移開始・悪い姿勢の継続開始・残り時間・サイクル・表示状態などを記録する。スコアを後から再判定して当時の表示とみなさない。録画時間と測定時間の対応を明示し、休憩や再登録を除いた継ぎ目でも同期を保つ。再生時は現在位置からペットの姿勢、アニメーション途中位置、拡大率、揺れ、時刻表示を復元し、シーク・一時停止・倍率変更でずれを累積させない。既存の測定中のアニメーション自体は変更しない。

### 4. 原本の保存と初期化

WebはIndexedDBにメタデータ、OPFSに動画ファイルを保存する。OPFSの専用Workerから512KiB単位で書き込み、対応環境ではSyncAccessHandleで逐次flushする。これは全量Blobのメモリ保持を避けるための実装上の選択である。Desktopはapp data配下の映像ファイルとSQLiteメタデータを使う。Desktopのファイル入出力は専用Tauriコマンドで行い、Webへネイティブ依存を持ち込まない。

録画や出力の全量をJavaScript配列・巨大なBase64・SQLiteの一つのJSONに保持しない。書き込み待ちが積み上がらない制御を設け、読み出し・出力も区間単位で扱う。同じ録画のチャンクと、別々に開始された録画ファイルを区別し、独立したMP4等を単純連結して一つの動画とみなさない。カメラ再接続等で分かれた場合は再生時の連続性と書き出し時の再構成を検証する。

コレクション初期化は全映像・ペット記録・アプリ内の出力一時データも対象とし、確認文に明記する。処理中の録画・出力を先に停止し、世代情報で遅れて届く書き込みによる復活を防ぐ。ファイル削除は再試行可能にし、失敗したのに消去完了とは表示しない。測定スコアと利用者が外に保存したファイルは保持する。日数による削除処理は実装しない。

### 5. 画面と設定

`ResultScreen`に結果からの入口、`ResultCard`にコレクションからの入口と表示用途の区別、`WorkApp`にタイムラプスと設定への遷移を追加する。`ResultCard`の保存・共有用描画は取得時レイアウトを使い、コレクション表示用の日時位置やタイムラプスボタンをPNGに混ぜない。現行の色、角丸、星、グラフ、エフェクト、共有・保存ボタンは保持する。

タイムラプス画面は確認済みFigmaを基準に、動画クリック／タップによる再生切り替え、一時的な中央アイコン、シークバーを追加する。シーク中・読み込み中・保存中・エラーの表示を用意する。映像内の測定ペットと動画外の装飾アナゴを別のコンポーネントとして扱い、外側2体は登場後の位置を固定する。設定は録画画質、ペットを含める選択、背景・左右アナゴを含める選択、共通の自由配置プレビューをまとめる。録画するかの選択はタイマー設定に置く。

操作フィードバックは動画を邪魔せず操作が通ったことを伝える目的とし、半透明の背景と明瞭な再生／一時停止アイコンを中央に表示する。motion-designを参考に、出現約120ms・短い保持・消失約180ms、合計約0.6秒を初期案として実画面で調整する。大きな移動や背景の常時アニメーションは加えない。連続操作では前の消去予約を取り消して最新の状態だけを示し、再生失敗を成功したように表示しない。Reduce Motionでは拡大縮小を省き、短時間の状態表示は残す。動画操作領域にフォーカスしたSpace／Enterでも切り替えられ、支援技術には現在の再生状態と操作を伝える。録画・保存動画にこの操作用オーバーレイを合成しない。

新しい登場演出はmotion-designで設計し、既存Lottieの利用・時刻指定再生の検証にはtext-to-lottieを使う。既存アニメーションの動作・タイミングを変更する必要が出た場合は先に利用者へ確認する。Reduce Motionは新しい入口演出と閲覧時の動きへ反映し、元記録を破壊せず、出力との違いが生じる場合は明示する。

### 6. 検証と受け入れ条件

- 記録OFFでは動画を保存しない。ONの選択と720p／1080pの設定が再起動後も保持される。実際の解像度を検査し、音声トラックがないことを確認する。
- 集中→休憩→集中、一時停止→再開、基準再登録／キャンセル、手動終了／自動終了、カメラ切断を検証する。除外区間が動画に入り込まず、映像の欠落を正常な完全記録と表示しない。
- 既知の時刻で姿勢とタイマーを変える短い検証動画を作り、1倍速・各倍率・シーク直後・再生終了・1倍速の書き出しで、ペットと残り時間・サイクルが一致することを確認する。同期精度の許容値は実機の録画経路を測定してから設定し、合格した実測値を報告する。
- 動画のクリック／タップ／キーボード操作で再生が切り替わり、中央アイコンが短時間で消えることを確認する。連打、自動再生の拒否、再生失敗、シークバーのドラッグ、Reduce Motionを確認し、誤切り替えや消えないオーバーレイがないことを検証する。
- 原本のみ、ペット込み、外側装飾込み、両方込みを保存・再読込し、保存動画に再生状態アイコンやシークバーが焼き込まれないことを確認する。再生倍率を16倍へ変えても保存ファイルは1倍速の尺を維持する。
- 代表的な長時間録画と区間を増やした検証を行い、メモリ・ディスク増加・出力待ち時間・キャンセル後の解放を測る。現在の最大設定120分×12サイクルは集中24時間となるため、短い検証だけで上限まで対応済みと報告しない。
- 再起動、未録画の古いカード、録画途中の終了、容量不足、保存失敗、同時初期化を検証する。初期化後に動画が復活しないこと、外部保存済みファイルとスコアが保持されることを確認する。
- Webの1512×982、720×512、390×844、およびmacOSアプリの実ウィンドウで、Figmaとの座標・余白・文字・色・画像比率と、見切れ・横スクロール・操作到達性を比較する。キーボード操作、タッチ、長い日本語／韓国語、読み込み・空・エラー状態も確認する。
- PiiiNとposture-appでそれぞれ`bun run build`、Desktopで`cargo check --manifest-path src-tauri/Cargo.toml`を実行する。同期・区間除外・世代更新／消去のテストを追加する。Windows等を実行できない場合は未検証として分離して報告する。

## 技術上の確認事項と根拠

- MediaRecorderのチャンク通知間隔は正確ではないため、チャンク数から録画時刻を算出しない。バックグラウンドや画面ロック時の遅延も検証する。[MDN: dataavailable](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)
- `isTypeSupported`は形式の能力検出であり、資源不足等で録画が失敗しない保証ではない。[MDN: isTypeSupported](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)
- コンテナを扱えることと、その端末で動画のエンコード／デコードが可能なことは別である。MediabunnyでもWebCodecs由来のコーデック可用性はブラウザに依存する。[Mediabunny: supported formats & codecs](https://mediabunny.dev/guide/supported-formats-and-codecs)
- 正式リリース時に7日保管へ変更する場合、既存の大会用映像の扱いは別途合意する。今回の実装に将来の自動切替を含めない。
- 実装・検証の進捗と実測結果は docs/timelapse-verification.md に分離して記録する。
