# ストーリーのウィンドウサイズ対応（2026-10-27）

## 修正

Web と desktop の `OnboardingStoryScreen.tsx` / `onboarding.css` を同期した。従来は幅1000px以下で横長のウィンドウも縦配置になり、960×600ではナビゲーションがy746pxまで押し出されていた。

- 横長は1512×982の基準構図を維持。幅679px以下または縦長・正方形で縦配置へ変更する。
- 縦配置のキャラクター領域は残り高さを使い、7体の仲間は幅から個別画像の重なりを保ったまま全体幅を計算する。長い文章は折り返す。
- カードは縦配置で横スクロール。必要な縦スクロールと下端の操作ボタンを維持する。
- 低い横長画面の本文は最小18px、開始ボタンは最小16px / 高さ44px。矢印の操作領域は横配置で最小44px、縦配置で56px。
- ResizeObserver はCSS変数だけを更新し、リサイズによるReactの再描画やLottieの再生成を避ける。
- Webインラインペットと開発用プレビューの最大幅に画面高さの制約を追加した。ネイティブペットの固定ウィンドウ設定、カタログ、モバイル契約は変更なし。

- desktop `bun run build`、`cargo check --manifest-path src-tauri/Cargo.toml`、`bun run tauri build --debug --bundles app`: 成功。

- macOSアプリのウィンドウ拡大と画面1/4への縮小を実行。縮小時のRetinaキャプチャは1712×1082px。キャラクターと操作ボタンの再配置を確認できたが、自動操作中に本文の登場とLottie再生が停止したため、ネイティブの全表示・モーション確認を合格とはしていない。座標による直接ドラッグは操作ツールがウィンドウを取得できず実行不能だった。

## 追加修正: ナビゲーションの基準と仲間の接地

ユーザーの再確認で、横長のウィンドウでも基準キャンバスが上下に余白を作る場合、仲間が実際の画面下端から離れることが判明した。960×800では88.254pxの隙間を再現した。上記の初回確認は「画面に収まる」ことに偏り、接地と画面端からの距離の検査が不足していた。

- ナビゲーションを縮小キャンバスの外へ移し、実際の画面左右を基準にした。最小ボタン寸法44px。1512×982では従来のx80/x1368・y355・64×64pxをそのまま維持する。
- 仲間の表示領域をキャンバス下の余白まで延長し、画面下端に揃えた。7画像ともアルファ領域が画像の最下行まで達することを確認した。
- 仲間の3.1秒ループは、全体を9px浮かせる動きから底辺固定の縦伸縮（1〜1.0225倍）に変更。頭の上下量・登場順・460msの登場時間を維持する。
- 縦画面の仲間シーンは、ボタンを左右中央の空き領域へ配置し、下端のキャラクターを覆わない。カード画面は下端の操作領域を保持する。

再測定: 1512×982 / 1920×720 / 1280×400 / 960×800 / 720×512 / 1000×999 / 768×1024 / 390×844 / 320×568。7体すべての画像下端と画面下端の差は最大0.003px（CSS丸め）、ページ横はみ出し0px。960×800の隙間は0px。1920×720の左右ボタン余白はどちらも58.65px、320×568の仲間シーンは左右16px・y256・56×56px。基準1512×982の位置差は0px。

Web/desktopのビルド、desktopのRustチェック・macOS debug bundle作成、Impeccable静的検査、両リポジトリのdiffチェックに成功。カードへの前後移動とブラウザconsole error/warnなしも確認した。macOSアプリで仲間シーンへの遷移は再実行したが、自動操作中のアニメーション停止が再現し、ネイティブでの接地の実画面検証は未完了。Windows実機も未検証。
