# 判定の根拠を部位別の案内につなぐ

2026-11-27。基準コミット `8844131`。

## 要求と範囲

ユーザー要求：肩中心と耳中心を結ぶ線の前後方向を区別してフィードバックにつなぐ。現在測定している値が悪い姿勢の判定原因なら、その原因に合う文言を表示する。

Web・macOS・Windowsの共通測定経路を変更する。既存の判定しきい値・得点・BADまでの待機時間・アニメーションは変更しない。原点は登録姿勢であり、医学的な診断をしない。原本映像・ランドマークや新しい説明情報のサーバー送信は追加しない。

## 実装

- 点数を計算する同じループから、使用された特徴の正規化偏差・信頼度と重みを反映した寄与を返す。説明側で点数式を再実装しない。
- 頭の傾き・過度な顔の回転という独立BAD条件を優先し、総合点によるBADでは現在の寄与が大きい特徴から選ぶ。表示中の原因が引き続き該当する場合は維持する。無関係な大きい観測値を原因として表示しない。
- 肩中心→耳中心のYZ角度に、観測した顔の前後方向による符号を添える。前なら「頭が前に出てるよ！」、後ろなら「頭が後ろに傾いてるよ！」。元の得点用角度の絶対値と片側偏差は維持する。横顔などで前後を確定できない場合は「頭と肩の位置を戻そう！」。
- 横ずれ、耳中心と肩中心の距離、実際の胴体軸、首角度、左右の耳肩距離のバランス、頭肩角度、顔幅加点を説明へ対応させる。方向が裏付けられる既存の顎・肩・顔接近の観測は該当する特徴に限って使う。
- 現在の値が回復してもEMAや状態遷移の待機が残る場合、別の小さな変化を新しい原因として断定しない。観測不能は既存の観測不能案内、未特定は一般案内を維持する。
- ローカルの説明記録をversion 3で区別し、終了コメントには実際の原因だけを集計する。version 2の過去記録は保持し、異なる版を連続時間として合算しない。ウィジェット・録画の発話イベント形式は変更しない。

- 共通測定・発話・終了集計・ウィジェット・タイムラプスの122テスト（1,887 assertions）、計測ラボ7テスト（62 assertions）、翻訳6テスト（3,133 assertions）が成功。

## 2026-11-28: 前方突出と頭肩距離が重なる場合の説明優先順位

利用者の指定により、BAD判定の重み・しきい値・回復条件を維持し、発話と終了コメントの原因選択だけを変更する。PR #53の先行案にあった回復条件変更・表示した発話時間の記録は取り除いた。

- 有効な前方移動（`headForward`、または前方向を観測した`headShoulderAngle`）と`headShoulderDistance`が同時に存在する場合、距離の説明を前方移動で代表する。後方・方向不明・前方根拠の欠損時には適用しない。他の部位の優先順位を一律に下げない。
- 距離の発話が先行していても、前方移動が確認された時点で前方の文言へ切り替える。既存の発話維持・姿勢回復・欠測の条件、表示モーションはそのまま。
- 終了コメントは同じ共通ルールで選択用の時間を積算し、前方と重なる距離の時間を二重に競わせない。距離のみの区間は距離として残す。元の原因別観測・活動時間と保存値は保ち、新しい保存/送信フィールドを追加しない。
- 最初に距離のみ、後に距離+前方となる入力で発話とカードの両方が距離を選んでしまう失敗を再現してから修正。距離24秒・前方20秒の例では、説明選択用は距離3秒・前方20秒となる（状態境界1秒は両端一致の既存規則により除外）。元の活動時間は24秒/20秒のまま。

回帰検証には初回同時検出、距離案内からの切り替え、方向不明・後方・欠測、独立した部位の維持、距離だけの長い区間、既存の回復文言を含める。これは合成入力の挙動検証であり、実カメラの測定精度の検証ではない。
