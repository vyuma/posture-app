## 変更

カード内の画像、名前、星、タグ、余白を 264×348 のカード座標系からカード幅に応じて拡縮する。選択画面に残っていた固定フォント・星サイズと、オトアナゴだけ異なる画像オフセットを除去。星は以前のユーザー指定どおり残す（Figma の選択画面サンプルには星がない）。オトアナゴのタグ背景は `#F0F0F0`。

小さいカードでは名前と星を上下に並べ、タグを折り返す。文字の下限は名前12px・タグ7px、星10px。カード高を内容に合わせるため、小画面では固定の縦横比より可読性を優先。

大きな選択キャラクターだけに穏やかな呼吸を追加。基本4.6秒、眠そうなオトアナゴは6秒、`ease-in-out`、開始遅延0.6秒。最大拡大は横1.012・縦1.009で、下端を支点とする。キャラクター変更時に開始し直し、非表示タブ・画面外では停止。Reduce Motion では停止する CSS を追加した。既存のカードホバー、選択枠、文字・吹き出しアニメーション、ホームの動きは維持。

縦長のプレビュー領域でも画像の元の縦横比を維持して下端まで届くよう、画像幅の下限を領域の高さから算出する。

画像枠と余白は比率から算出した値との差が0.01px未満。Figma の未選択オトアナゴのカード外寸179.79×237pxに対して、実装の外寸は幅約1.87px・高さ約2.59px大きい。外側の3列グリッド幅は維持し、今回の対象である内部比率を修正した。小さいタグには7pxの下限があり、厳密な比例値6.88pxとは約0.12px異なる。

17種すべてについて画像の可視領域、名前、星、タグを確認。Web・Desktop の画像、カタログ、既存の画像表示設定は一致している。シマアナゴとオトアナゴは画像内部の透明領域が異なるため、画像要素の箱だけでなく頭・胴体の見える位置も参照した。

## 実行した検証

- Chrome: 1512×982 / 1920×1080 / 720×512 / 390×844。17カードでページの横はみ出し、名前・星・タグの領域外はみ出しなし。390px幅では最後のカードまでスクロールし、キーボードで選択可能。
- macOS の実際の Tauri / WKWebView 検証アプリ: 1512×982 / 1200×752 / 720×512 の画面を確認。1512px はシマアナゴ・オトアナゴの2枚で Figma と比較。

- Chrome のオトアナゴ70フレームでは頭の上端が約3.72px移動し、画像下端の差は0.001px未満。6秒周期は算出スタイルでも確認。
- 0枚の空状態、決定ボタンの無効化、変更キャンセル、Enterによる選択・決定、ホームへの反映を確認。ブラウザーのコンソールエラーなし。
- 両リポジトリの `bun run build` 成功。Desktop の `cargo check --manifest-path src-tauri/Cargo.toml` 成功。両方の `git diff --check` 成功。

## 制限・残る差

- Figma の静止サンプルには星がないため完全なピクセル一致を目標としていない。星を表示する過去の要件を優先した。
- UI は SF Pro 優先のフォントスタック。日本語フォールバックとOSの文字描画、スクリーンショットのカラープロファイルによる見え方の差はある。Windows 実機、VoiceOver、OS の Reduce Motion 設定変更は実行していない。
- 開発用ツールバーはスクリーンショット下端に表示される。通常の製品画面には表示されない。
- 最初の非表示設定の検証アプリでは描画が抑制されていたため、表示される検証アプリへ切り替えて再検証した。
- 既存のビルド警告（lottie の eval、チャンクサイズ、Web の Tauri import、Rust の未使用 pairing コード）は残る。今回の変更でエラーは発生していない。
- コミット・プッシュは行っていない。既存の未コミット変更は保持。
