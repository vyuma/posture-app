- 1512×982、1200×800、720×540、390×844で表示を比較。角丸は40 / 31.75 / 30 / 30px。背景のヒーロー色を曲線の背後まで延長し、影も維持。

## 登録画面の閉じる画像の欠落修正

Desktop へ登録画面を移植した際、参照先 `/x.png` のコピーが欠落していたため破損画像になっていた。Web と同じ112×112pxの原本を `public/x.png` に追加し、ビルド出力にも同一バイトが含まれることを確認。1512×982、1200×780、720×540のフロントエンド実画面で画像デコード・画面内配置・閉じる→ホーム復帰を検査。1512pxではFigmaの `(1376,56)` / 56×56、1200pxでは約44.44×44.44。登録画面とロゴが直接参照する他の画像にも欠落がないことを確認。Desktop build通過。

## 初期ウィンドウを1200×780に設定

Desktop の初期コンテンツ領域を1200×780論理pxへ変更。起動時に現在のモニター（取得できなければ主モニター）の work area を読み、Dock・タスクバーを除いた領域からタイトルバー等の外枠と16pxずつの余白を引いて計算する。高DPIの物理pxを論理pxへ換算し、1200:780を保って縮小する。小さい画面では通常の最小サイズ720×540も表示可能サイズ以下へ下げる。使用可能領域の中央に配置してから表示し、起動時の大きすぎるウィンドウのちらつきを避ける。起動後のリサイズ比率は固定しない。

サイズ計算のRustテスト3件通過。1920×1040、2倍DPI、1366×728、1280×680、150%表示、1024×560、800×480の作業領域を対象に、外枠・余白込みの収まりと比率を検証。frontend build通過。実物の小型モニター・Windows上でのネイティブ起動は未検証。モニター変更に常時追従して自動リサイズする機能や前回サイズ保存は追加していない。
