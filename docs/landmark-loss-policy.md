# ランドマーク欠落時の案内とピーン率

2026-10-30（JST）。ユーザーが比較説明後に「그렇게 바꿔줘」と承認した変更。Web PiiiNとDesktop posture-appへ同じドメイン動作を反映。モバイル契約、キャラクター、既存アニメーションは変更しない。

## 動作

- 基準登録後に観測できた鼻・左右の耳・左右の肩を対象にする。画像座標の既存visibility閾値0.5を使用。腰が映らないだけでは欠落扱いにしない。
- 必須点が見えなくなってから1秒未満は`grace`。ペットの直前の姿勢と既存の吹き出しの時刻を保持し、称賛や具体的な理由を新規発行しない。
- 新しいカメラフレームが届いたまま1秒以上欠落すると`missing`、ペットはbadとして既存の怒り・成長を使用し、`姿勢を戻して！`を一度表示する。欠落だけから顔の接近などを断定しない。
- 再観測が350ms続くまで欠落警告を解除しない。その後は既存のgood回復判定350msと称賛の安定確認350msを通す。合成100ms間隔のUIでは再観測から回復称賛まで約1.1〜1.2秒だった。
- 初めから観測できない場合、休憩・一時停止・再登録後にまだ観測できていない場合は`unavailable`。これだけでbadにしない。
- 同じ`video.currentTime`の再推論を抑止する。readyState不足、停止・無効・muteしたカメラトラックは判定保留。観測が古くなった場合もbadや称賛の新しい根拠にしない。エンジンの観測間隔が1500msを超えた場合は欠落の連続時間をリセットする。

## 記録との区別

- 欠落警告は姿勢を戻すための動作規則であり、身体の状態を確定した測定値ではない。欠落中は従来通り`qualityOk=false`、グラフは`untracked`かつscore=null。0点や直前の点数で穴を埋めない。
- 新規セッションに`ratioBasis: focus-v1`を保存する。ピーン率は「観測できた良い姿勢の時間 / 全集中時間」。休憩・一時停止・基準再登録時間は分母に含めない。カメラ停止・追跡失敗中も集中タイマーが動いていた時間は分母に含める。
- 1分good + 9分untrackedは10%。有効観測が全くない場合は比率なし・獲得なし。既存の獲得閾値50%は変更しない。
- 旧セッションに新しい基準を遡及適用しない。`ratioBasis`のない保存済みカードは有効時間基準を保持し、移行済み`legacyGoodRatio`も保持する。
- 新しい案内は既存の`general`発話イベントで記録される。タイムラプスの保存形式、過去の発話、Lottieキーフレームは変更しない。

## 吹き出し表示の追補

一般の表示は6.5秒、姿勢警告は15秒。途中の状態変更は300msの退場後に新しい案内へ切り替える。最初の称賛前のカメラepoch更新で表示権を消費しない。500ms以内の一時的な無効観測では既存イベントと終了時刻を保持し、それを超える判断不能は非表示にする。新イベントの繰り返し生成はしない。既存録画の時刻は維持。両環境50テストとビルド、Rust検査成功。Chromeの合成入力で警告と称賛の表示を確認。実カメラと今回のネイティブ画面は未確認。

表示時間の再調整: 自然終了は320msでフェードしながら3px下降、切替後は280msの登場。フレームごとの補間にCSS transitionを重ねず、期限で突然消える見え方を抑制。切替待機後にも登場を再生し、元の終了時刻は延長しない。今回の変更は両方37テストで確認。実画面のモーション再確認は未実施。

## 怒っている間の継続表示（最新）

ユーザーの追加指示により、新しい警告には `whileBad: true` を付け、ペットがbadの間は15秒の期限を越えて表示する。一般の吹き出しは6.5秒のまま。2.6秒周期、最大±1.2度の小さい揺れを共有描画関数に追加。表示中のopacityは1を維持し、Reduce Motionでは揺れない。別の理由・回復・休憩・一時停止への切替は既存の300ms退場を使用し、その間の揺れを固定して退場と競合しないようにした。長い観測停止では非表示になり、新しいbad観測が戻った場合は警告を復元する。

`whileBad`のない過去録画は従来の期限どおり。新規録画はJSON・時間変換・seekを通してフラグを保持し、Canvasも同じ描画関数とposeを使用する。データ量は毎フレーム増やさない。

検証: Web/Desktopとも53テスト・1169assertions成功、両build・cargo check成功。Chrome 1710×951で15秒を十分越えても`姿勢を戻して！`のopacity=1を確認。別時点の変換行列の回転成分は-0.0204158と+0.0108782で、緩やかに両方向へ揺れることを確認。通常の称賛への切替と表示も確認。証跡はWeb `output/landmark-loss/persistent-speech.png`。macOS QAのメイン画面で発話イベントを確認できたが、別ウィジェット窓のモーションは確認できていない。実カメラ・動画ファイルの新規エクスポートは今回未実行。
