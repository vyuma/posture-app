## 사용자 의도

펫의 `顔が近い！` 같은 대사를 실제 측정 근거에 연결한다. 시간이 지났다는 이유로 특정 원인을 말하지 않으며, 무엇을 보고 그렇게 판단했는지 설명 가능하게 한다.

## 구현 전 확인한 코드

웹과 데스크톱의 posture engine/score/types/spec, Widget/widgetPresentation, timelapse/model 파일 내용은 동일하다. 각 원격 main은 웹 d3c75b7e8b357e12ded0627b7a128a8a86e400cd, 데스크톱 7c0f7f865f45abdacdf039c3c3ce1d7279742bef, 모바일 053104b4c8348ed0f6cec5406cf87e066001f628로 확인했다. 분석 대상은 미커밋 변경을 포함한 현재 로컬 코드다.

- `src/features/work/widgetPresentation.ts`: 좋지 않은 상태의 시간에 따라 `widgetGrowth`를 5초 동안 0→1로 계산한다. `widgetMessage`는 growth ≥ .98이면 `顔が近い！`, 그 전에는 `姿勢を戻して！`. 실제 얼굴 거리나 원인 코드를 받지 않는다. Reduce Motion에서는 growth가 0이므로 같은 측정이라도 해당 대사가 나오지 않는 구조다.
- `src/features/work/Widget.tsx`: WidgetState는 bad/badSince와 타이머 정보를 전달하며 원인/추적품질 필드가 없다.
- `src/features/work/WorkApp.tsx`: 펫의 bad는 유효하고 최신인 측정 AND isBadPosture일 때만 켜진다. 인식 불가 시 bad=false가 되어 현재 표시상 good/いい感じ로 갈 수 있다. 인식 불가를 좋음과 분리하는 설계 검토가 필요하다.
- `src/features/posture/engine.ts`: 기준 대비 머리 좌우 위치, 귀–어깨 거리, 상체 축 각도, 목 각도, 귀–어깨 비대칭, 머리 전방 각도를 계산한다. 얼굴/몸 방향도 보며 가중 점수와 시간 기준으로 good/bad/hold를 결정한다.
- `headWidthRatio`는 **귀 사이 거리 / 어깨 너비**다. 얼굴과 카메라 사이의 실제 거리가 아니다. 기준 대비 1.3배를 넘으면 점수 보정이 시작되고 1.6배에서 최대 0.35를 더한다. 옆모습에서는 이 보정을 하지 않는다.
- `engine.pose.geometry.ts`: 목/머리 각도는 절댓값 각도이고 여러 점수 정규화도 절댓값 차이를 쓴다. 큰 점수만 보고 앞/뒤/왼쪽/오른쪽을 단정하면 안 된다. 방향에 맞는 대사에는 부호가 있는 별도 근거가 필요하다.
- 골반이 보이지 않을 때 상체 축은 수직축을 대신 사용한다. 이 값을 등 굽음의 근거로 사용하면 안 된다.
- 어깨를 한 번 인식한 뒤 400ms 이상 놓치면 엔진 내부에는 forceBadState 경로가 있다. 단, WorkApp의 quality gate 때문에 이것이 곧 펫의 bad나 실제 점수 감점으로 표시된다고 단정할 수 없다.
- 타임랩스 PetEvent에는 원인/대사 기록이 없다. `paintWidget`도 pose/growth에서 문구를 다시 만들므로, 당시 실제 대사를 재현하려면 별도 기록이 필요하다.

## 사용한 구분

- 관측 근거: 기준보다 어떤 특징이 어느 방향으로 변했는지와 현재 관측 가능 여부.
- 판정 이유: 관측 근거가 충분하고 일정 시간 지속됐을 때 안내할 수 있는 변화 유형. 신체 문제를 확정 진단한다는 뜻이 아니다.
- 인식 상태: 얼굴/어깨 누락, 오래된 프레임, 기준 없음 등으로 지금 판단 가능한지 여부. 좋은 자세와 구별한다.
- 펫 대사: 판정 이유 또는 인식 상태에 연결하는 사용자 안내. 펫의 크기나 성장 시간과는 별도다.

사용자가 확정한 자세 변화 이유·얼굴 접근·머리 전방 이동·머리와 몸의 좌우 기울기·인식 불가는 CONTEXT.md에 기록했다. 가역적인 문구 매핑만으로 ADR을 만들지는 않는다.

## 설계 구조

1. 기존 엔진과 분리한 관측기가 원인 후보, 사용한 근거, 기준 구간을 반환하고 기존 스냅샷에 최신성/관측 가능 여부를 함께 전달한다. confidence는 보정된 정확도 확률이 아니므로 사용자에게 정확도 %로 표현하지 않는다.
2. 추적 가능 여부를 먼저 확인한다. 관측이 불충분한데 구체적인 원인이나 `いい感じ！`를 말하지 않는다.
3. 기준 대비 얼굴 접근, 머리 전방 이동, 좌우 기울기 등 **실제 검증을 통과한 항목**만 구체 대사로 연결한다. 기존 unsigned 각도나 귀/어깨 비율 하나만으로 원인을 정하지 않는다.
4. 인식 가능한 상황에서 기존 판정이 bad이지만 원인을 특정할 수 없으면 `姿勢を戻して！`로 안내한다. 근거 부족은 판정 보류 또는 일반 안내로 처리하며 ‘등이 굽었다’로 보완하지 않는다.
5. 여러 원인의 관측·지속·해제를 각각 추적하면서, 현재 안내만 유지 시간/근거 강도로 한 개를 고른다. 현재 원인이 해소되면 남아 있는 확정 원인을 새 말풍선으로 안내한다. 작은 수치 변동으로 문구가 계속 바뀌지 않도록 진입/해제 및 전환 규칙을 둔다. 수치는 검증 후 확정한다.
6. 기존 Lottie, 성장, 본체 흔들림을 대사 원인과 분리하고 그대로 유지한다. 말풍선의 등장·작은 흔들림·퇴장은 이전 사용자 요청 범위에서 연결한다. 그 밖의 애니메이션 변경은 별도 확인한다.
7. JSON은 원인 코드→일본어 대사 매핑에 사용한다. 측정 판정은 TypeScript에서 수행한다. 이 기능은 개별 캐릭터 성격 대사와 별개다.
8. 웹/데스크톱에 같은 판정 의미를 적용하고 플랫폼 전송부는 각자 유지한다. 영상 재생에는 기록된 원인/대사를 사용하고, 원인이 없는 과거 기록에서 새 원인을 만들어내지 않는다.

## 확정한 결정

1. **1차 검증 범위**: 얼굴 접근·머리 전방 이동·좌우 기울기. 실제 검증을 통과한 항목에 한해 구체 대사를 사용한다. 근거가 부족하면 일반 안내를 사용하며, ‘등 굽음’ 추정은 이번 범위에서 제외한다.
   - 사용자 답변: “얼굴 접근·머리 전방 이동·좌우 기울기부터 검증하고, 근거가 부족하면 일반 안내 (추천)”
   - 얼굴 접근과 머리 전방 이동은 구분한다. 전자는 카메라에 대한 상대적 접근, 후자는 어깨/몸에 대한 머리 위치 변화다.
   - 이 결정은 세 종류를 현재 정확히 판별할 수 있다는 검증 결과나 점수 변경 승인으로 해석하지 않는다.

2. **기존 점수 기준 유지**: 점수·좋음/나쁨·ピーン率·카드 획득 기준을 변경하지 않는다. 펫 안내에 필요한 근거 분류와 전달만 개선한다.
   - 사용자 답변: “점수 기준 유지, 근거에 맞는 펫 안내 개선 (추천)”
   - 새 원인 분류만으로 기존 good 판정을 bad로 바꾸거나 추가 감점하지 않는다. 기존 점수 가중치, 임계값, 판정 지속시간, 유효 시간 계산과 획득 규칙은 유지한다.
   - 같은 입력과 기준 자세에서 기존 점수·상태·ピーン率·획득 결과가 유지되는지 비교 검증한다.
   - 인식 불가를 좋은 자세로 칭찬하지 않는 안내 규칙은 점수 변경과 별개이며, 결정 3에 따른다.

3. **인식 불가가 지속되면 한 번 안내**: 짧은 누락에는 새 안내를 띄우지 않고, 판단 불가가 지속될 때 인식 안내를 한 번 표시한다. 같은 인식 불가 상태가 계속되는 동안 반복 발행하지 않는다.
   - 사용자 답변: “지속되면 인식 안내를 한 번 표시 (추천)”
   - 인식 불가 중 새 `いい感じ！`나 구체적인 자세 지적을 발행하지 않는다. 기존 점수·시간 집계는 결정 2대로 유지한다.
   - 인식 복구 후에는 새롭고 유효한 관측으로 대사를 다시 판단한다. 누락 이전의 원인을 그대로 새 안내의 근거로 사용하지 않는다.
   - 일반 인식 안내 예시는 `姿勢を確認できないよ`. 얼굴·어깨 누락이 확인됐을 때만 해당 부위에 대한 안내를 후보로 삼는다. 오래된 프레임 등 다른 사유를 얼굴·어깨 누락이라고 단정하지 않는다.
   - 통합 계획 승인에 따라 초기 지연은 2초, 문구는 `姿勢を確認できないよ`로 구현했다.

4. **동시에 보여주는 안내는 한 가지, 남은 원인은 이어서 안내**: 충분히 지속되고 근거가 가장 뚜렷한 변화 하나를 현재 안내로 선택한다. 다른 원인도 계속 추적한다. 변화가 없는데 확인된 원인들을 일정 주기로 순환하지 않는다.
   - 사용자 답변: “가장 근거가 뚜렷한 한 가지만 안내 (추천)”
   - 추가 사용자 확인: 얼굴 접근과 머리 기울기가 함께 있을 때 얼굴 접근을 먼저 안내했더라도, 얼굴 접근만 해소되고 기울기가 남으면 추가 말풍선이 나와야 한다.
   - 작은 수치 변동으로 대사를 바꾸지 않는다. 현재 원인이 유효한 동안에는 다른 변화의 근거가 충분히 뚜렷해졌을 때만 안내를 전환한다. 현재 원인이 해소되면 이 경쟁 우위 조건을 요구하지 않고, 계속 확정 상태인 나머지 원인 중 하나를 새로 안내한다.
   - 추가 사용자 확인: A만 안내한 뒤 A와 B가 함께 해소됐다면 B를 뒤늦게 말하지 않는다. 모든 원인의 현재 상태를 재확인하고, 유효한 good이 안정적으로 유지될 때만 칭찬한다.
   - 예: 얼굴 접근 A와 머리 기울기 B가 모두 확정 → `顔が近い！` → A 해소, B 지속 → `頭が傾いてるよ！`. A의 말풍선이 이미 사라졌어도 B는 새 말풍선으로 표시한다. B가 이미 유지시간을 충족했다면 A 해소 후 처음부터 다시 기다리지 않는다.
   - 현재 안내의 근거가 사라졌다면 해당 원인을 계속 주장하지 않는다. 유효한 다른 원인이 없으면 기존 자세 판정에 맞는 일반 안내로 돌아가고, 인식 불가 시에는 결정 3을 따른다. 남은 확정 원인이 있는데 중간에 `いい感じ！`를 표시하지 않는다.
   - 근거 강도는 보정된 정확도 확률이 아니다. 서로 단위가 다른 원시 각도/비율 숫자를 직접 비교해 우선순위를 정하지 않는다. 항목별 검증과 유지/전환 조건을 통해 비교한다.

5. **관측된 변화를 짧게 설명하는 대사**: 행동 제안보다 확인된 변화 자체를 짧게 말한다.
   - 사용자 답변: “확인된 변화를 짧게 설명 (추천)”
   - 얼굴 접근 `顔が近い！`, 머리 전방 이동 `頭が前に出てるよ！`, 머리 좌우 기울기 `頭が傾いてるよ！`, 몸 좌우 기울기 `体が傾いてるよ！`.
   - 충분히 판단할 수 있는 상황에서 기존 판정이 bad지만 원인을 특정할 수 없으면 `姿勢を戻して！`.
   - 머리 기울기만으로 몸 전체가 기울었다고 말하지 않는다. 단순한 머리 좌우 이동이나 얼굴 회전도 기울기와 구별한다.

## 승인된 통합 구현 계획

### 1. 점수와 분리한 관측·이유 분류

- `src/features/posture/`에 관측 근거 추출과 이유 선택 모듈을 추가하고, `engine.ts` / `engine.types.ts` / `hooks/usePostureTracking.ts`에서 필요한 입력을 전달한다. 현재 score 계산에 주입하는 특징값·가중치·quality 조건은 바꾸지 않는다.
- 기존 랜드마크와 기준 자세를 이용한다. 새 AI 모델이나 네트워크 추론을 추가하지 않는다. 이유 판정용 기준 통계가 필요하면 기존 점수 기준과 별도로 보관한다. 예전 기준 데이터에 해당 정보가 없으면 일반 안내로 동작하며, 새로 등록하기 전까지 임의로 기준을 만들어내지 않는다.
- 얼굴 접근은 얼굴의 영상 내 크기 변화, 방향 및 신뢰할 수 있는 다른 크기 단서를 함께 검토한다. 귀 너비/어깨 너비 하나 또는 world z 절댓값을 얼굴 거리로 사용하지 않는다. 머리 전방 이동은 어깨/몸에 대한 상대적이고 방향이 있는 근거를 사용한다.
- 머리 기울기는 신뢰할 수 있는 얼굴 지점의 기울기, 몸 기울기는 실제 관측된 상체 축으로 구분한다. 골반 누락 시 대신 넣은 수직축을 몸 기울기 근거로 쓰지 않는다. 거울 표시와 영상 종횡비에 영향을 받지 않는지 확인한다.
- 카메라 이동·줌과 사람의 접근은 단일 카메라에서 혼동될 수 있다. 관측만으로 구분할 수 없으면 특정하지 않는다. 카메라/해상도/기준 구간 변경은 후보와 유지시간을 초기화한다.
- 대사는 유효하고 최신인 관측과 원인별 확정/해제 상태로 선택하며, 기존 good/bad의 전환 이벤트에만 의존하지 않는다. 하나가 해소돼도 다른 확정 원인이 남으면 다음 안내를 발행한다. 기존 점수·good/bad 판정·ピーン率·획득 결과는 변경하지 않는다. 전체 점수가 회복했더라도 충분한 근거로 확정된 원인이 남아 있다면 구체 안내를 우선하고 `いい感じ！`를 끼워 넣지 않는다. 인식 불가나 불확실한 관측만으로 원인을 유지하거나 새 칭찬을 만들지 않는다.
- 지속시간은 프레임 수가 아닌 관측 시각을 기준으로 계산한다. 짧은 가림/일시 동작, 낮은 신뢰도, 오래된 관측은 후보 유지시간을 쌓지 않는다. 이유별 진입·해제 임계값과 교체 우위는 테스트 자료로 보정하고 설정값과 근거를 기록한다. 진입 지속시간은 기존 bad dwell 1.2초를 출발점으로 비교하되 정확도 검증값으로 주장하지 않는다.

### 2. 대사 데이터와 표시 이벤트

- 별도 `postureFeedback.json`에 이유 코드와 일본어 문구를 대응한다. 캐릭터 선택 화면의 성격 대사 JSON과 측정 원인을 섞지 않는다.

| 표시 조건 | 문구 | 확정 상태 |
| --- | --- | --- |
| 얼굴 접근 근거 충분 | 顔が近い！ | 사용자 확정 |
| 머리 전방 이동 근거 충분 | 頭が前に出てるよ！ | 사용자 확정 |
| 머리 좌우 기울기 근거 충분 | 頭が傾いてるよ！ | 사용자 확정 |
| 몸 좌우 기울기 근거 충분 | 体が傾いてるよ！ | 사용자 확정 |
| 유효한 bad, 구체 원인 불충분 | 姿勢を戻して！ | 사용자 확정 |
| 인식 불가 지속 | 姿勢を確認できないよ | 통합 계획 승인 |
| 확정된 지적 원인이 없는 유효한 good / 휴식 / 일시정지 | いい感じ！ / ストレッチした？ / お疲れさま！ | 기존 문구 유지 |

- `WorkApp.tsx`에서 표시 이벤트를 한 번 결정해 웹 펫, 데스크톱 오버레이, 타임랩스에 전달한다. 각 화면이 성장률로 서로 다른 대사를 만들지 않는다. 이벤트에는 ID, 문구, 이유, 시작 시각, 표시 종료 시각을 둔다. 매 프레임/타이머 갱신으로 재등장하지 않는다.
- 상태 또는 현재 안내할 확정 이유가 바뀔 때 한 번 표시한다. 같은 상태에 대한 주기적 반복은 추가하지 않는다. 복구 후 다시 같은 문제가 발생하면 새 사건으로 안내한다. 작은 수치 변동으로 문구가 순환하지 않도록 유지 규칙을 적용한다.
- 모든 원인 후보의 지속/해제 상태와 현재 선택된 원인, 말풍선의 보이는 여부를 분리한다. 말풍선 자동 퇴장은 원인의 해소를 뜻하지 않는다. 퇴장만으로 다음 원인을 순환시키지 않지만, 원인 해소로 안내 대상이 바뀌면 새로운 발화 이벤트를 만든다. 한 번의 bad 구간에서 한 번만 말하는 제한은 두지 않는다.
- 먼저 안내한 원인이 해소됐을 때 이미 확정 상태인 다른 원인은 즉시 다음 안내 대상으로 선택한다. 아직 진입 조건을 충족하지 않았거나 관측이 끊긴 후보는 기다리거나 보류한다. 과거에 발견됐다는 이유만으로 대기열에서 꺼내 말하지 않는다. 남은 후보가 여러 개면 그 시점에 가장 근거가 뚜렷한 하나를 고른다.
- 인식 불가 안내의 초기 제안은 연속 2초 후 한 번이다. 판단을 잃은 동안 기존 구체 지적이나 칭찬은 끝내고, 새 문구는 이 대기시간 후 표시한다. 복구하면 새 유효 관측으로 다시 판정한다. 기존 점수의 누락 처리시간과는 별도 설정이다.
- 세션 시작/종료, 휴식, 일시정지, 기준 재등록 시 이전 후보와 표시 예약을 정리한다. 재개 시 과거 원인을 그대로 재발행하지 않는다. 늦게 도착한 이전 기준의 관측은 제외한다.

### 3. 말풍선과 기존 펫 모션

구현 전 코드에는 말풍선 상시 표시와 180ms 문구 페이드만 있었고, 자동 퇴장과 말풍선 전체의 작은 흔들림은 없었다. 해당 요청을 아래처럼 연결한다. 본체 Lottie·상태 전환·5초 확대·지속 흔들림의 키프레임과 타이밍은 유지한다.

- 목적은 짧게 말을 건네고 작업에서 시선을 돌려주는 것. 말풍선에만 효과를 추가한다.
- 초기 제안: 약 220ms ease-out 등장 → 900ms 동안 좌우 끝이 번갈아 위아래로 움직이는 ±1.5° 회전 2회 → 시작 후 약 3.5초까지 유지 → 180ms ease-in 퇴장. 기본 기울기는 유지하며 작은 회전은 내부 래퍼에 적용한다. 총 표시시간은 약 3.68초이고 실화면 읽기 속도에 맞춰 조정한다.
- 새 안내가 확정되면 이전 예약을 폐기하고 최신 이벤트만 표시한다. 점수가 아니라 실제 메시지 ID를 기준으로 발화하며 반복 렌더링으로 모션을 다시 시작하지 않는다.
- Reduce Motion은 대사 선택에 영향을 주지 않는다. 이동·회전 없이 같은 문구와 표시 기간을 제공한다. 읽기 보조기술에는 한 번에 전체 문구를 전달한다.
- 긴 `頭が前に出てるよ！`와 `姿勢を確認できないよ`가 현재 고정 폭에서 잘릴 수 있으므로 말풍선만 필요한 만큼 넓히거나 읽기 좋은 줄바꿈을 적용한다. 펫/타이머 전체를 줄이지 않는다. 화면 경계와 네이티브 창의 보이는 범위를 확인한다.

### 4. 타임랩스·플랫폼 호환

- 새 녹화는 실제 표시 이벤트의 문구·원인·표시 구간을 선택 필드와 별도 피드백 버전으로 기록한다. 매 프레임 랜드마크나 원본 카메라 정보를 추가 저장하지 않는다. 기존 영상 원본을 다시 인코딩하거나 수정하지 않는다.
- 휴식·일시정지 등 제외 시간을 반영한 녹화 시간축에 발화 구간을 대응하고, 미리보기와 합성 내보내기가 같은 재생 시각에서 같은 문구·숨김 상태를 사용하도록 한다. 시크·배속 변경 시 표시 타이머를 새로 시작하지 않는다.
- 과거 영상에는 새 판정 이유를 소급해서 붙이지 않는다. 피드백 기록이 없는 영상은 기존 표시 재현 경로를 유지한다. 그 경로의 `顔が近い！`는 과거 프로그램의 문구일 뿐 새 분류기가 검증한 얼굴 접근으로 취급하지 않는다. 이미 외부에 저장한 영상은 그대로다.
- desktop `work_widget_update`는 현재 JSON Value를 전달하므로 새로운 optional 필드가 유실되지 않는지 확인한다. 기본 창 높이 계산·버튼 동작·드래그·확대는 유지한다. Web에는 Tauri 어댑터를 추가하지 않는다.
- 수정 대상은 PiiiN 웹과 posture-app 데스크톱. 캐릭터 ID·카탈로그·획득 이벤트·모바일 통신 계약은 바꾸지 않으므로 vibe-app에 새 필드나 UI를 복제하지 않는다.

### 5. 영향 파일과 검증 순서

| 영역 | 주요 대상 | 검증 |
| --- | --- | --- |
| 근거 추출/선택 | posture 신규 모듈, engine/types, usePostureTracking | 입력 품질·방향·기준 재등록·점수 동등성 |
| 대사 전달/표시 | WorkApp, Widget, widgetPresentation, widget.css, 신규 JSON/표시 이벤트 | 한 가지 선택·반복 방지·인식 불가·모션 보존 |
| 영상 재현 | timelapse model/recorder/compositor 및 paintWidget | 새 기록 문구/숨김 일치·과거 기록 호환·시크·내보내기 |
| 네이티브 전달 | desktop platform 및 work_widget_commands | 필드 보존·실제 macOS 오버레이·창 경계 |

1. 같은 랜드마크 입력·기준 자세를 기존/수정 경로에 재생해 score, good/bad/hold, 유효 시간, ピーン率, 획득 결과가 같음을 확인한다. 분류기에 입력을 추가하면서 기존 점수 입력을 바꾸지 않았는지 검사한다.
2. 제어 가능한 입력/시각으로 여러 원인 경쟁, 짧은 누락, 오래된 프레임, 인식 불가의 한 번 안내와 회복, 세션/기준 변경, Reduce Motion에서 같은 문구를 검증한다. 특히 A+B 확정 → A 안내 → A만 해소 → B 새 안내를 검증한다. A 말풍선이 표시 중/퇴장 후인 경우, 총점 상태가 유지/회복하는 경우 모두 확인한다. B가 먼저 해소됐거나 근거를 잃은 경우에는 오래된 B를 안내하지 않아야 한다. B가 지속되는 동안 반복 렌더링으로 재발화하지 않는지도 확인한다.
3. 아래 실제 카메라 사례에서 관측 가능한 원인과 오검출/판정보류를 구분해 기록한다. 합성 입력 테스트 통과를 실제 자세 분류 성능으로 주장하지 않는다. 충분히 검증되지 않은 원인은 일반 안내를 유지한다.
4. 웹 1512×982 / 720×512 / 390×844와 실제 macOS 앱에서 모든 문구, 최대 확대, 등장·퇴장, 상태 변경 도중의 모션, 타이머/버튼 접근성, 화면 경계 잘림을 확인한다. 기존 디자인과 변경 부위만 비교한다. Windows는 실행 환경이 없으면 미검증으로 명시한다.
5. 새/과거 타임랩스의 재생, 시크, 1/16배속 및 펫 포함 저장·공유 파일 재열기를 확인한다. 기존 합성 내보내기에서 보고된 디코더 실패가 남아 있으면 실행 성공으로 보고하지 않고 이번 변경과의 관련성을 분리한다.
6. 양쪽 `bun run build`, 관련 posture/widget/timelapse/session 테스트, desktop `cargo check --manifest-path src-tauri/Cargo.toml`, `git diff --check`를 실행한다. 성능은 기존 카메라 추론 빈도와 추가 처리 비용을 비교한다. Git push/merge는 이 계획에 포함하지 않는다.

## 다음 단계

웹·데스크톱 초기 구현은 반영했다. 실제 카메라로 라벨링한 사례의 분류 검증과 임계값 보정, macOS 실제 수동 드래그, 현재 환경에서 실패한 영상 디코더 경로 검증이 남아 있다. 네이티브 대사 표시·퇴장·버튼은 잠금 해제 후 확인했다. 구체 대사의 초기 분류기는 합성 랜드마크로 검증했으며 실사용 분류 정확도가 검증된 것으로 간주하지 않는다. 현재 반영본을 릴리스 검증 완료본으로 보고하지 않는다.

## 검증할 사례

카메라 고정 상태에서 정상/머리만 앞으로/의자 전체 전진/몸 좌우 기울임/얼굴만 돌림/물건을 잡기 위한 일시 이동/얼굴·어깨 가림을 구분한다. 카메라 이동·각도·줌 변화, 정면과 측면, 골반이 없는 상반신 구도, 어두운 환경, 재기준 설정, 백그라운드 지연도 확인한다. 원인별 오검출과 판정 보류를 기록하며 임계값을 수치로 지어내지 않는다.

실카메라 분류 성능 검증은 아직 하지 않았다. 초기 구현의 합성 입력 테스트는 실카메라 정확도 검증을 대신하지 않는다. 낮은 가시성, 골반 누락, 얼굴 회전, 줌과 구별할 수 없는 크기 변화 등 관측상 근거가 부족한 입력은 구체 이유를 보류한다.
