# タイムラプス実装・検証記録

2026-10-28。Web: PiiiN、Desktop: posture-app。Mobile / LAN契約 / キャラクターID・カタログは変更していない。既存の作業差分は保持している。この作業ではコミット・push・mergeはしていない。

## 実装

- タイマー設定の録画選択は初期オフ、選択を記憶する。720p標準、プロフィール → 設定から1080pを選択。
- 同じカメラの映像トラックを複製して録画。音声なし。集中中だけ記録し、休憩・一時停止・基準再登録を除外。
- WebはOPFSのファイル＋IndexedDBメタデータ、Desktopはアプリデータのファイル＋SQLite。512KiB単位で処理し、録画・出力の全量をJS配列に溜めない。Mediabunnyは録画確定／出力時に遅延ロードする。
- 原本と時刻付きのペット状態を保存。ペットのポーズ遷移・拡大・揺れ・残り時間・サイクルを再生時刻から復元する。既存のWidget/PetRigとLottie原本は変更せず、版付きの同一JSONを再利用。
- 動画を開くと1倍速。動画を押す／Space・Enterで切り替え、中央の操作表示は620msで消える。シークバー、1→2→4→6→8→16→1、終了時停止、再クリックで先頭再生。
- 出力は常に1倍速。既定はカメラのみ。ペットと外側の背景・アナゴを別々に選択できる。映像内のカメラとペットは共通設定で自由移動・拡縮。左右の装飾アナゴは入場後固定。
- カメラのみの標準配置なら再エンコードなし。合成出力の解像度は原本を超えず、次回録画用の画質設定を変えても既存原本の解像度を落とさない。
- 共有シート非対応／開けない環境では単一ファイルを保存して添付する案内。共有キャンセルでは別のダウンロードを開始しない。Desktopはダウンロードフォルダに書き出す。外部サービスへの自動投稿はない。
- コレクション初期化で全アプリ内動画・状態ログ・出力一時ファイルを削除。世代チェックで遅延書き込みによる復活を防止する。測定記録と外部保存済みファイルは保持。日数による削除なし。
- 録画障害は測定を止めない。原本を保持して部分記録／失敗を表示する。動画尺と録画時計の差が0.25〜1秒の許容幅を超える場合も部分記録にする。
- コレクションの日時位置を変更。カードPNGは取得時の右上日時へ戻し、タイムラプスボタンを含めない。狭い画面ではボタンを外した後の高さを再計算する。

主なコード: `src/features/timelapse/`、`src/features/work/WorkApp.tsx`、`ResultCard.tsx`、`TimerSettings.tsx`、`src/lib/shareResultCapture.ts`。Desktop固有の保存処理は `src-tauri/src/commands/timelapse_commands.rs` と `src/features/timelapse/platform.ts`。DesktopUpdaterは保持。

## 制限と残る確認

- macOSの冷間カメラ開始テストには開始遅延とみられる約0.88秒の尺差があった。原因を確定したものではない。最終コードでは短い動画でも0.25秒を超える不一致を部分記録として知らせるよう変更した。この変更後にカメラを再取得したテストは権限／取得待ちでタイムアウトし、実カメラによる再確認は完了していない。本番は基準測定後の稼働中カメラを記録するため、実際の計測開始→休憩→再開の通し確認が残る。
- macOSのバックグラウンド合成テストではタイマー・canvasの更新頻度が落ち、18秒の予定に対して14.026667秒の集中映像になる回もあった。Webの119.991秒の結果を、macOSでの長時間・バックグラウンド時の精度保証へ読み替えない。
- 長時間の実カメラ記録、負荷時のメモリ使用量、Windows/WebView2、実機iPhone/Android、実サービスの共有シート・Discord添付は未検証。ファイル生成と保存までを確認した。
- Webの保管は端末・オリジンのブラウザ領域に依存し、ブラウザ側のデータ消去・ストレージ回収に対する永久保存の保証ではない。Webの一時出力ファイルはダウンロード中の破損を避けるため次回起動時または初期化時に削除する。
- 開発中のHMRで古い保存オブジェクトが残り、保存後表示が100%のままになる問題を確認した。片付け処理が失敗してもUIを必ず解除するよう修正し、新規ロードで保存完了を確認した。
- 既存警告: lottie-webのeval、500kB超のchunk、無効化中のペアリングRustコードの未使用警告。ビルドエラーはない。
