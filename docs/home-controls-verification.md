## 실행 확인

- 브라우저 실화면: 위 6개 크기, 17종 획득 카드의 이름·별·태그 영역 측정. 가로 넘침과 카드 내부 문구 잘림 없음.
- 0개 컬렉션: 0/111, 미획득 111칸 표시. 시험용 데이터만 사용했다.
- 정렬 메뉴: Enter → 방향키 → Enter 선택 및 닫힘, 키보드 포커스 복귀 확인. 포인터용 파란 포커스를 추가하지 않았다.
- 페이지 전환: 선택 화면의 opacity 0.997451 → 1을 실행 중 확인, 로고 opacity는 1 유지. 콘솔 error 0건.
- macOS Tauri QA 앱: 1200×752에서 홈의 5열·홈→타이머 이동, 720×512에서 3열·카드 스크롤 접근 확인. 두 화면의 흰 로고 실제 픽셀 경계(2배 스크린샷)는 모두 (133,161)–(279,207)로 동일하다.
- 1512×982 native 크기로도 전환했으나 디스플레이 바깥 영역은 스크린샷에서 비어 보여 전체 화면 검증 근거로 사용하지 않았다. 해당 크기의 전체 검증은 브라우저에서 수행했다.
- 웹/데스크톱 `bun run build` 성공. 데스크톱 `cargo check --manifest-path src-tauri/Cargo.toml` 성공. 기존 번들 크기/Lottie eval/Rust 미사용 코드 경고는 남아 있다.
- Impeccable 변경 대상 정적 검사: 결과 `[]`. React 훅 순서, 정리 함수, 화면 재마운트 여부를 검토했다.

## 한계와 유지 사항

- Reduce Motion일 때 새 전환을 건너뛰는 분기는 구현/코드 검토했다. 현재 브라우저 도구는 해당 OS 설정을 에뮬레이션하지 않아 실제 설정 변경 검증은 하지 않았다.
- Windows 네이티브 실행은 하지 않았다. macOS는 실제 WKWebView에서 검증했다.
- 비교 원본은 1장 획득/별 없는 초기 카드이고 테스트 화면은 17종/별 있는 현재 카드다. 카탈로그 순서·문구·자산과 기존 모션은 이번 작업에서 바꾸지 않았다.
- 비교 PNG의 색상 외관은 캡처 경로마다 다르게 보이므로 픽셀 RGB 완전 일치를 주장하지 않는다. 변경한 버튼의 computed 색상은 원본 CSS(글자 #13A2D7, 소개 배경 white 20%)로 확인했다.
