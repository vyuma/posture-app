# 測定画面の更新・検証（2026-10-29）

## 対象

PiiiN Web と posture-app デスクトップの表示を更新。測定・録画の保存形式、エンジンのカウント時間、タイマー入力規則、モバイル通信契約は変更していない。vibe-app は対象外。

## 変更

- `タイムラプスを記録する` をタイマーからプロフィール → 設定へ移動。既存の `TimelapseSettings.enabled` と保存処理を使用し、初期値 OFF・選択記憶を維持。
- 準備ボタン下の状態説明、測定中の補足説明、メイン画面のサイクル数、登録画面下のキャンセル文字ボタンを削除。ヘッダーの X とアクセシブル名は維持。
- 登録画面を白いパネル・横長カメラ・中央の円に変更。以前横に置かれていた `PetRig pose="good"` は静止フレームであり、再生中のアニメーションではなかった。
- カウントと円は既存エンジンの `warmupRemainingMs` を使用。5→4→3→2→1→DONE。完了表示と画面遷移の既存タイミングは変更なし。
- SVG の実周長を使い、約80msのエンジン更新を直接描画。WKWebView では CSS の dashoffset transition を付けると実行確認中に全周が残って見えたため、追加の CSS transition は使わない。独立したタイマーや常駐 RAF ループを製品コードに追加していない。
- 測定・休憩・一時停止のパネル、カメラ、下部ボタン、罫線を共有。休憩は横長タイマーカード、一時停止の左ボタンはユーザー指定どおり `再開`。
- カード説明は右側の余分な余白と均等折返しを除去。シマアナゴの文言・フォントサイズは維持。狭い画面では自然に折り返す。
- タイマーの三桁入力、1分入力・5分スライダー、1周時の休憩0分のロジックは維持。矢印・閉じるアイコン、590のフォントウェイトも添付に合わせた。

## 実行確認

- Web: 1512×982、720×512、390×844 で prepare / ready / active / rest / pause / timer。横方向オーバーフローなし。短い画面では縦スクロールで操作ボタンへアクセスできる。
- Web: 登録中の実行キャプチャで5,4,3,2,1,DONEとSVG進行値を確認。`arc-samples.json`、`registration-countdown.gif`。
- macOS: 実際の Tauri WKWebView（PiiiN Story QA、localhost:1420/dev/work）で1512×982の各画面、1200×752の登録カウントダウン、720×512の小窓を確認。720pxではネイティブ自動化のスクロール操作が `noWindowsAvailable` で失敗したため、ネイティブのホイール操作による下部到達は未検証。Web側のスクロール到達は確認済み。
- Web / macOS: プロフィール → 設定に録画チェックボックスがあり、タイマーには無い。Webの表示用fixtureで設定を閉じて再度開いたときの選択維持を確認。製品の永続化は既存 `saveTimelapseSettings` に接続したまま。
- Web: シマアナゴのコレクションカード説明は18.0476px、行高21.4849px、実高21.4844pxで1行。保存PNGも1行で、取得時のカード配置と透明な角丸を維持。
- 入力・チェックボックス・既存ドロップダウンのアクセシブルラベルを維持。Webのキーボードによる下部ボタンへのスクロールを確認。Reduce Motion時の追加装飾アニメーションはない。OS設定を切り替える実機検証は未実施。
