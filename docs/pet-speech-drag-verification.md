# 펫 안내 점멸 수정과 웹 이동 검증

2026-10-29. 웹 PiiiN과 데스크톱 posture-app의 기존 미커밋 작업 위에 필요한 변경만 적용했다. push/merge는 하지 않았다. 모바일의 캐릭터·페어링 계약은 변경하지 않았다.

## 원인과 변경

- `FeedbackSpeech.choose(null)`이 현재 표시뿐 아니라 마지막으로 안내한 의미까지 지웠다. 전체 상태는 good인 채 800ms마다 한 번의 짧은 인식 누락, 미확정 후보, hold 관측을 각각 넣은 8초 테스트에서 칭찬이 **각 10회** 발행되었다. 안정적인 good 대조군은 1회였다.
- 이제 일시 보류는 표시만 숨긴다. 같은 상태로 돌아와도 새 ID/등장 효과를 발행하지 않는다. 실제 다른 원인, good↔bad, 휴식/일시정지, 새 세션/기준으로 전환하면 해당 안내는 계속 가능하다. A 해소/B 지속, 둘 다 해소의 기존 동작도 회귀 테스트를 통과했다.
- 점수용 `qualityOk`와 별도 원인 관측기의 `available`을 기존 훅에서 한 유효성으로 묶고 있었다. 현재 점수가 유효한 bad이고 세부 원인만 불명확하면 `姿勢を戻して！`. 추적 자체가 무효/오래된 경우에는 무응답. 이유 관측을 보류한 good도 칭찬하지 않는다.
- 새 안내에서 `姿勢を確認できないよ`를 제거했다. 이미 기록한 영상의 문구와 시각은 다시 쓰지 않으며, 과거 `unavailable` 이벤트는 읽을 수 있다.
- 점수 엔진·ピーン率·보상·본체 Lottie·성장·흔들림·말풍선 모션 수식은 바꾸지 않았다. 모션 자체를 다시 만드는 수정이 아니다.

## 웹 펫 이동

`Widget.tsx`, `useWidgetDrag.ts`, `widgetPosition.ts`, `widget.css`에 웹 전용 조작을 추가했다.

- 캐릭터/말풍선을 드래그. 타이머·일시정지·종료 버튼은 드래그와 분리.
- 방향키 10px, Shift+방향키 40px. 키보드 포커스 표시.
- pointer capture, 종료·취소·포커스 이탈 처리. 브라우저 뷰포트 안에서 본체 마스크, 회전한 긴 말풍선, 타이머/그림자를 포함해 경계를 보정.
- 성장/리사이즈로 보정한 위치는 유지해 축소 시 이전 위치로 튀지 않게 했다. 새로고침/펫 재마운트 시 기본 위치로 시작한다. 브라우저 밖으로 이동하는 기능은 아니다.
- 데스크톱의 네이티브 드래그 경로와 영상 합성의 자유 배치 설정에는 손대지 않았다.

- 점수 엔진 출력 동일성, Lottie 키프레임 보존, 오래된 영상 이벤트, 재생/시크, 실제 상태 전환 후 재안내도 검사했다.

Chrome 실제 UI(합성 관측, 실제 카메라 아님):

- Good jitter 시나리오 14.5초 실행 이력에 `0.4s いい感じ！` **한 번**만 남음.
- 원인 관측 불가+bad: `0.0s 姿勢を戻して！`. 더 이상 인식 불가 문구를 발행하지 않음.
- 1512×982에서 포인터 드래그로 타이머 기준 좌표가 (1274,893) → (924,623) 이동. 놓은 뒤 dragging 상태 해제.
- 720×512에서 창 밖 방향으로 드래그해도 말풍선의 실제 회전 영역 top=13.35px, 마스크 left=13px/top=46.57px, 타이머 left=8px/top=212.57px로 남음. 방향키 한 번 뒤 타이머 left=18px. Shift+방향키 40px 이동도 확인.
- 390×844에서 최대 성장 마스크 291×639px. 오른쪽 아래로 드래그 후 마스크 (91,132)–(382,771), 타이머 (164,761)–(342,826)로 창 안 유지. good으로 돌아와도 타이머 위치 (164,761) 유지.
- 이동 뒤 일시정지→재개, 종료→위젯 제거 확인. 최종 코드 새로고침 뒤 다시 드래그/키보드/성장/종료 검증.
- 개발 도중 훅을 추가하면서 Fast Refresh의 훅 순서 오류가 한 번 발생했다. 페이지를 새로 로드한 뒤 검증했으며 이후 새 런타임 오류는 없었다.
- 경계 수학 테스트는 1512×982, 720×512, 390×844 외에 320×568까지 확인. 물리적 터치 기기/OS Reduce Motion은 이번에 실행하지 않았다.

macOS 앱:

- 실행 중인 `PiiiN Timelapse QA`의 `/dev/work`에서 수정 코드의 시나리오를 직접 실행. good jitter 이력은 `0.4s いい感じ！` 한 번, 원인 불명 bad 이력은 `0.0s 姿勢を戻して！`로 확인.
- 메인 WebView의 안내 발행 이력과 화면은 저장했지만 **별도 네이티브 펫 패널의 새 말풍선을 직접 캡처하지 못했다**. 이번 결과를 네이티브 패널의 시각 검증 완료로 취급하지 않는다.
- 검증 펫을 숨겼으며 테스트 창 크기와 브라우저 뷰포트 오버라이드는 복원했다.

증적은 웹 checkout `output/pet-speech-drag/`의 웹 스크린샷과 native 안내 이력에 있다. `web-drag-720-final.jpg`는 최종 코드의 이동/키보드 화면이다.

## 남은 확인 사항

첨부 카드(4분/88%)에는 센서 원본과 발화 이벤트가 없으므로 사용자 세션의 정확한 원인을 역으로 확정할 수 없다. 이번에는 코드상의 재현 가능한 중복 발행 원인을 수정했다. 급격한 그래프 변화의 원인이 실제 움직임인지 랜드마크 흔들림인지는 별도 실카메라 기록과 비교해야 한다. 원인별 임계값은 아직 실카메라 정확도 보정이 남아 있으며, 이번 수정으로 분류 정확도까지 검증한 것은 아니다.
