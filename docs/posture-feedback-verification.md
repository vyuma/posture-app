# 자세 근거별 펫 안내 구현·검증

2026-10-29. 사용자 승인 후 웹 PiiiN과 데스크톱 posture-app에 반영했다. 커밋·push·merge는 하지 않았다. 기존 미커밋 작업은 보존했다.

## 반영 범위

- `posture/feedback.ts`: 기존 랜드마크에서 얼굴 크기 변화, 머리 좌우 기울기, 실제 골반이 보이는 몸 축, 방향을 가진 머리 전방 이동 근거를 별도로 수집한다. 기존 점수 엔진으로 되돌려 보내지 않는다.
- `posture/feedbackSpeech.ts`, `postureFeedback.json`: 모든 후보의 지속·해제를 추적하고 안내는 하나만 선택한다. A 해소/B 지속이면 새 B 발화, 동시 해소면 B 생략. 자동 퇴장만으로 다른 원인을 순환하지 않는다.
- `usePostureTracking`, `types`, `work/model`: 새 기준 통계를 선택 필드로 저장·복원한다. 카메라·해상도·기준 구간이 바뀌면 이전 후보를 초기화한다. 예전 기준 기록은 일반 안내로 호환된다.
- `usePostureSpeech`, `WorkApp`, `Widget`, `WidgetSpeech`, `widgetPresentation`, `widget.css`: 하나의 발화 ID와 실제 문구·시작·끝을 웹/오버레이에 전달한다. 얼굴 지점 인식 불가도 칭찬과 분리한다. 말풍선 내부만 220ms 등장, 900ms 작은 흔들림, 180ms 퇴장; 전체 3.68초. 본체 키프레임·성장·상태 전환은 변경하지 않았다.
- `timelapse/model`, `recorder`, `composition`, `paintWidget`: 새 영상에 실제 발화와 기록 시간축을 저장한다. 시크·배속 재생에서 문구를 다시 발행하지 않는다. 피드백 버전이 없는 과거 영상은 기존 표시 경로를 유지한다.
- `FeedbackPreview`, `WorkPreview`, `TimelapsePreview`: 실제 카메라와 분리된 개발용 재현 시나리오. `scripts/posture-feedback.test.ts`에 원인 추출, 상태 전환, 점수 보존, 재생 테스트를 추가했다.

위 변경은 양쪽 저장소에 포팅했다. 공유 구현·테스트 19개 파일은 바이트 단위로 동일함을 확인했다. desktop WorkApp의 기존 업데이트 UI 및 플랫폼 전달부는 보존했다. Rust의 위젯 상태 전달은 기존 JSON Value 경로를 사용한다. 모바일 계약·캐릭터 카탈로그는 바뀌지 않아 vibe-app을 수정하지 않았다.

## 초기 판정값과 한계

다음은 보수적으로 선택한 초기 구현값이며, 실카메라 데이터로 보정된 정확도나 의학적 기준이 아니다. 현재 구체 안내에 사용되지만 실제 카메라 분류 검증은 아직 남아 있다.

- 필요한 얼굴·어깨 지점의 가시성 ≥ 0.7, 프레임 안에 있는 유효한 좌표만 사용.
- 얼굴 접근: 귀/눈 너비 각각 최소 18% 증가와 어깨 대비 최소 12% 증가가 함께 필요. 눈·귀 변화가 서로 다르거나 전체 줌/이동과 구분하기 어려우면 보류.
- 머리 기울기: 눈과 귀의 일치하는 변화, 초기 12°. 몸 기울기: 실제 관측된 골반–어깨 축 변화, 초기 10°.
- 머리 전방: 몸 축을 연장한 위치에 대한 머리 이동을 얼굴 방향에 투영하고 어깨 너비로 정규화. 초기 0.18. 골반 누락·방향 변화는 보류.
- 기준 구간의 변동이 크면 위 최소값보다 5×MAD 조건을 우선한다. 근거 강도는 확률이 아니다.
- 진입 1.2초, 해제는 강도 0.65 미만 350ms. 다른 후보가 0.5 이상 강한 상태를 1.2초 유지할 때만 현재 원인과 경쟁해 교체. 현재 원인이 해소되면 이미 지속 조건을 채운 다음 원인을 즉시 선택한다.
- 인식 불가 2초 후 한 번, 안정적인 good 350ms 후 칭찬. 같은 프레임 반복이나 오래된 관측으로 원인 유지시간을 쌓지 않는다.

단일 카메라에서 줌·카메라 이동·의자 이동과 얼굴 접근을 항상 구분할 수는 없다. 측면/골반이 없는 구도에서는 전방 이동·몸 기울기 안내가 보류될 수 있다. ‘등이 굽었다’는 이유를 만들지 않는다. 실카메라 검증 없이 이 초기 구현을 분류 정확도 검증 완료로 취급하지 않는다.

## 자동 검증

양쪽에서 동일하게 실행:

`bun test scripts/posture-feedback.test.ts scripts/widget.test.ts scripts/timelapse.test.ts scripts/work-session.test.ts`

각각 **43 tests / 341 assertions / 0 failures**. 관측기를 붙이기 전후 140개 입력의 전체 엔진 출력을 비교해 기준 등록·점수·상태·회복이 동일함을 확인했다. 기존 세션/ピーン率/획득 테스트도 통과했다. 본체 Lottie 레이어와 키프레임 보존 테스트가 통과했다.

- 웹 `bun run build`: 통과.
- desktop `bun run build`: 통과.
- desktop `cargo check --manifest-path src-tauri/Cargo.toml`: 통과. 기존 미사용 pairing 관련 경고 32개.
- 양쪽 `git diff --check`: 통과.
- 빌드에 기존 Lottie eval, 큰 번들 경고가 남아 있다. 웹에는 기존 Tauri 동적/정적 import 혼용 경고도 있다.

새 AI 모델·추론 요청·카메라 프레임 빈도 변경은 없다. 별도 실기기 CPU/GPU 성능 비교는 하지 않았다.

## 브라우저 실행 검증

IAB `localhost:1450/dev/work`의 명시된 합성 관측 시나리오를 실제로 실행했다. 이는 실제 카메라 판정 테스트가 아니다.

- A→B: 0.0s 일반 안내 → 1.2s `顔が近い！` → 6.4s `頭が傾いてるよ！` → 10.8s `いい感じ！`. A 말풍선 퇴장 후에도 B가 새로 등장했다.
- 둘 다 해소: 일반 안내 → 얼굴 접근 → 6.8s 칭찬. 머리 기울기 안내가 뒤늦게 나오지 않았다.
- 표시 중 DOM에서 opacity 0.8076→0.9999, y 0.577→0.0003px를 관측했다. 별도 회전 측정에서 0→1.31676→0.586144° 변화를 확인했다. 전체 모션 수식과 Reduce Motion의 정적 표시·동일 문구/시간은 단위 테스트로 확인했다. OS Reduce Motion 설정을 바꾸는 실행 검증은 하지 않았다.

최대 성장과 긴 `頭が前に出てるよ！` 말풍선의 회전 후 bounding box:

| 뷰포트 | x / y | 폭 / 높이 | 결과 |
| --- | --- | --- | --- |
| 1512×982 | 1217.10 / 157.18 | 220.38 / 106.90 | 텍스트·말풍선 프레임 안, 가로 넘침 없음 |
| 720×512 | 464.33 / 23.69 | 177.66 / 72.40 | 텍스트·말풍선 프레임 안, 가로 넘침 없음 |
| 390×844 | 95.10 / 19.18 | 220.38 / 106.90 | 텍스트·말풍선 프레임 안, 가로 넘침 없음 |

이번 범위는 새 말풍선의 표시·폭 확장이며 Figma 전체 재디자인을 하지 않았다. 기준 각도/색/본체 배치는 유지했다. Figma 전체 요소의 새 오차 측정을 완료했다고 주장하지 않는다. 스크린샷과 DOM 측정은 웹 저장소 `output/posture-feedback/`에 있다.

## 새 녹화·재생 검증

`/dev/timelapse`에서 카메라 대신 테스트 캔버스로 녹화. 결과 MP4 1280×720, 11.991초, 878,579bytes. 실제 발화 ID/문구/시각이 기록되었고 휴식 제외 후 시간축으로 연결됐다.

- 3.6초로 시크하면 `顔が近い！`, 7.6초로 시크하면 `頭が傾いてるよ！`가 기록된 모습으로 표시되는 것을 스크린샷으로 확인.
- 1→2→4→6→8→16 배속 변경, 실제 video.playbackRate=16과 끝까지 재생 후 정지를 확인. 저장·공유 버튼의 1배속 표시는 유지.
- 새 이벤트의 취소·표시 만료·시크·과거 이벤트 호환은 자동 테스트 통과.
- 합성 저장 검증은 원본 디코딩 단계에서 `This video track cannot be decoded in this environment`로 실패했다. 이는 기존 `widget-design-verification.md`에도 기록된 환경 경로다. HTML video 재생은 가능하지만 WebCodecs를 사용하는 내보내기는 실패했다. 실제 저장 파일 재열기·공유 성공은 확인하지 못했다.

## 잠금 해제 후 macOS 추가 검증

2026-10-29, 사용자의 잠금 해제 응답 후 기존 Tauri `PiiiN Widget QA` 앱에서 실행했다. 개발용 합성 관측이며 실제 카메라 분류 테스트는 아니다.

- `main`의 `/dev/work` → Rust `work_widget_update` → 별도 `PiiiN character` 패널(`/overlay.html`)까지 새 문구가 전달됨을 실제 AX와 화면으로 확인했다.
- A→B 실행 기록: 0.0s 일반 안내, 1.2s 얼굴 접근, 7.2s 머리 기울기, 12.2s 칭찬. 메인 창이 배경/최소화 상태인 실행에서는 웹 전면 실행보다 타이머 간격에 따른 지연이 있었다. 이를 고정 1.2초 응답 성능으로 주장하지 않는다.
- 둘 다 해소 실행 기록: 0.0s 일반 안내, 1.9s 얼굴 접근, 8.9s 칭찬. 머리 기울기 문구를 뒤늦게 발행하지 않았다.
- 최대 펫 패널 360×822 논리 픽셀(캡처 720×1644)에서 `頭が前に出てるよ！` 전체가 창 안에 들어오는 실제 화면을 저장했다. 이후 같은 창에서 텍스트와 말풍선이 사라지고 본체·타이머가 남은 화면도 저장했다. 투명 창을 흰 배경으로 캡처하므로 흰 말풍선 외곽과 투명 영역의 경계를 픽셀로 구분하는 비교는 하지 않았다.
- 네이티브 펫의 일시정지→재개 버튼과 자세 이미지 전환, 타이머를 눌러 메인 창 복귀, 종료 버튼을 눌러 메인 창 복귀·펫 닫기를 확인했다. QA 버튼 검증이므로 실제 측정 데이터 저장을 실행한 것은 아니다.
- 메인 창의 720×512, 1200×752, 1512×982 크기를 실제로 전환했다. 펫은 메인 창과 별도인 패널이다. 마지막에는 원래 1200×752로 복원하고 검증 펫을 종료했다.
- 드래그는 두 번의 자동 입력으로 실제 이동을 확인하지 못했다. 기존 위치 파일에도 변화가 없었다. 자동 조작의 제한인지 실제 수동 드래그 문제인지는 이 결과만으로 구분할 수 없어 미검증으로 남긴다.
- 네이티브 창 전환 후 도구의 부분 AX 갱신이 이전 창 정보를 반환하는 경우가 있어 전체 AX를 다시 읽고 스크린샷을 함께 확인했다. 제품 코드 변경 없이 검증 기록만 갱신했다.

증적: 웹 checkout의 `output/posture-feedback/native-speech.png`, `native-speech-expired.png`. 기존 빌드·자동 테스트 결과는 위와 같고 이번 후속에서는 제품 코드를 바꾸지 않아 다시 실행하지 않았다.
