# 深度プローブ研究ページ

アプリの深度プローブ（`src/features/posture/depth/`）が**画像のどこから、どんな値を読んでいるか**を目で確かめるための開発用ページです。本番と同じワーカー・同じ読み取り関数を使い、深度マップ全体を受け取って可視化します。本番ビルドには含まれません。

```sh
bun run research:depth
# または bun run dev のあと http://localhost:1420/research/depth-probe/ を開く
```

## 何を測っているか

1. **深度マップ**：Depth Anything V2 Small が出すのは、メートル単位の距離ではなく**相対的な逆深度（視差）**です。値が大きいほどカメラに近く、フレームごとに未知のスケールとオフセットがかかります。
2. **読み取り位置**：MediaPipe の耳（7, 8）と肩（11, 12）のランドマークをそのまま使うと、輪郭の端に乗って背景を拾います。そこで少し内側に寄せた位置を使います。
   - 耳：鼻の方へ `earInwardRatio`（既定 0.25）
   - 肩：肩の中点の方へ `shoulderInwardRatio`（既定 0.2）
3. **パッチの中央値**：上の位置を中心に、半径が肩幅 × `patchRadiusRatio`（既定 0.06）の正方形の中央値を読みます。耳が2つ見えていれば平均します。
4. **指標**
   - `耳−肩 = 耳の視差 − 肩の視差`：正なら頭が肩より手前にあります。
   - `正規化 = (耳−肩) / フレームの p5–p95 幅`：フレームごとのスケールの揺れを打ち消すためです。
   - `基準から = 正規化 − 最初の 5 秒間の中央値`：正なら、基準時より頭が前に出ています。

## 画面の見方

| パネル | 見るポイント |
| --- | --- |
| 推論に送ったフレーム | 橙の枠（耳）と緑の枠（肩）が、髪・背景・服の境界ではなく身体の上に乗っているか |
| 深度マップ | 頭・首・肩が背景から分離して見えるか。破線は下の断面の位置 |
| 縦断面 | 首の中心を上から下へたどった視差。頭を前に出すと、耳の高さの線が左（近い側）へ動くはず |
| 横断面 | 肩の高さで左右にたどった視差。肩の枠（縦線）が平らな部分に乗っていれば安定。崖の上に乗っていれば背景が混入している |
| パッチの中身 | p10–p90 の幅が他のパッチより極端に大きければ、そのパッチは境界をまたいでいる |
| 深度の時系列 | 耳・肩・耳−肩（背景合わせ）と旧指標が、ラベルの区間でどちらへどれだけ動くか |
| 比較の時系列 | 深度を使わない Face の前方移動（cm）と MediaPipe の頭部前傾角 |
| 判定（画面上部） | ラベルごとの平均±標準偏差と d′、それに基づく H1 / H2 の判定文 |

## 検証したい問い

「頭を前に出しても深度の値がほとんど動かない」のはなぜか。原因を次の 2 つの仮説に切り分けます。

| 仮説 | 内容 | どう見えるか |
| --- | --- | --- |
| **H1 モデルの限界** | 単眼の深度モデルは人物と背景の差は出せるが、人物の内側の数 cm の凹凸は平らに潰す | 頭が実際に前に出ていて、体ごと近づいたときは反応するのに、耳−肩差は分離しない |
| **H2 指標の問題** | 旧指標はフレーム全体のレンジ（ほぼ背景で決まる）で割るため、変化が埋もれる | 背景合わせした耳−肩差では分離するが、旧指標では分離しない |

### 比べる信号

- **旧指標**：`(耳−肩)/フレームの p5–p95 幅` の、基準からの変化。アプリに入っているもの。
- **背景合わせ**：人物の外側（深度マップ上の白い破線の外）の画素で、各フレームの深度を基準フレームに `a·D + b` で最小二乗合わせします。そのうえで耳・肩それぞれの基準からの変化を、基準フレームのレンジ比で出します。フレームごとにかかる未知のスケールとオフセットを、背景は動かないという前提で打ち消すための処理です。
- **Face**：MediaPipe Face Landmarker の変換行列から頭までの距離（cm）を出します。肩までの距離は肩幅の画素数に反比例するとみなし、「頭が肩より何 cm 手前に出たか」の基準からの変化を求めます。深度モデルを使わない比較対象であり、**頭が実際に前に出たかの確認**にも使います。
- **MediaPipe 頭部前傾角**：アプリの既存の指標。

### 判定のしかた（画面上部に自動で出ます）

ラベルの切り替え直後 1 秒は姿勢の移行中なので除外します。良い姿勢との分離度は `d′ = (平均の差) / √((分散₁ + 分散₂)/2)` で測ります。

1. **データ量**：「良い姿勢」「頭を前に出す」がそれぞれ 10 件以上あること。
2. **操作の確認**：Face で頭が 2 cm 以上前に出ていること。出ていなければ判定不能。
3. **陽性対照**：「体ごと近づく」で、耳の変化の d′ が 2 以上であること。2 未満なら、背景合わせかパイプラインの問題。
4. **本題**
   - 耳−肩の d′ ≥ 1 かつ旧指標の d′ < 1 → **H2 指標の問題**
   - 耳−肩の d′ ≥ 1 かつ旧指標の d′ ≥ 1 → 深度で検出できている（表示スケールの問題だった）
   - 耳の d′ ≥ 1 だが耳−肩の d′ < 1 → 頭は近づいて見えるが、肩も一緒に動いて打ち消されている
   - それ以外 → **H1 モデルの限界**

しきい値は `verdict.ts` の先頭にあります。

## 実験の手順

1. 背景が動かない場所で正面に座る。背景に奥行きのあるもの（棚、壁の角など）が映っていると背景合わせが安定する（R² が 0.9 以上が目安）
2. 「基準を取り直す」を押し、5 秒間良い姿勢を保つ
3. 「記録開始」を押し、数字キーで切り替えながら、各 10 秒ずつ姿勢をとる
   - `1` 良い姿勢 → `2` 頭を前に出す（顎を突き出すように、はっきり）→ `1` → `2` → `1` → `5` 体ごと 10 cm ほど近づく → `1`
4. 画面上部の判定を見る。「記録停止」→「CSV を保存」で生データも残せる
5. 入力解像度を 518 にして同じことを繰り返し、H1 が解像度で改善するかを見る

## 既知の限界

- 相対深度なので、同じ姿勢でも背景や照明が変わると「正規化」の値が動きます。基準は同じ環境で取り直してください。
- フレームの p5–p95 幅は背景の奥行きで決まるので、背景の近い・遠いが変わると正規化の分母も変わります。
- 髪が耳を覆うと、耳のパッチは頭の側面ではなく髪の表面を読みます。
- 横を向くと耳の片方が隠れ、もう片方は頭の後ろ寄りを読むので、値が変わります。
- 表示は左右反転していません（アプリのプレビューは鏡像です）。
- Face の距離は MediaPipe の標準の顔モデルとカメラ画角を仮定した値です。絶対値は数割ずれる可能性がありますが、基準からの変化として使っています。
- 肩までの距離を肩幅で推定しているので、猫背で肩が内に入ると「肩が遠ざかった」と読み、Face の前方移動を大きく見積もります。
- 背景合わせは、背景が平らな単色の壁だとスケールが決まりません（R² が下がります）。
